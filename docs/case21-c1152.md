# 编号 21 · C1152 同负载对照

以紧凑 KV 版的 **2,144.23 tok/s/卡** 为参照，追加吞吐目标是 **2,251.45 tok/s/卡**，且每轮的稳态平均 TPOT 小于 **50 ms**。W4A8 组合的两轮确认中位数为 **2,344.55 tok/s/卡（+9.34%）**，达到目标。精度复审后，带 SiLU 保护的保留版完成一轮同负载复测，测得 **2,330.28 tok/s/卡（+8.68%）**，平均 TPOT **35.41 ms**。 [逐轮指标](../results/case21/c1152.json)

## 对照条件

Ascend A3 0.32.0rc1、DeepSeek V4.1 Flash 1017 W4A8、共享 Engram Host VMM 回移。P 和 D 各 8 张物理卡、16 DIE。P 使用 DP4/PCP4/TP1，D 使用 DP16/TP1/EP16 和 DSpark 5。P renderer=4 从第二个阶段起固定。D 的本地前缀缓存与 SWA bounded replay 关闭。HCCL 缓冲与图捕获的变化列在对应阶段。 [共用设置](benchmark.md) · [Host VMM 回移](../patches/README.md)

所有计分轮使用同一批 **4,608 条、131,072 输入 token、1,024 输出 token** 的请求，客户端并发上限为 **1,152**，发压速率不限。稳态按 AISBench 的请求发起时间选样，D 单卡输出除以 8 张物理卡。表中两个轮次的阶段取中位数，带保护版是一轮复测。 [逐轮指标和精度计数](../results/case21/c1152.json) · [逐请求记录](../results/case21/c1152-requests.csv.gz)

## 逐阶段实测

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原部署，P renderer=1 | 2 | 1,222.56 | 21.75 | 24.64 | 96.93 | 216.0 |
| 只加 P renderer=4，原始 D | 2 | 1,711.98 | 27.15 | 30.67 | 57.94 | 377.1 |
| MoE 缩容、有效行 SwiGLU、Host VMM embedding | 2 | 1,868.59 | 28.44 | 31.54 | 47.81 | 439.0 |
| 再加 KV 紧凑布局 | 2 | 2,144.23 | 32.51 | 35.84 | 31.99 | 594.1 |
| 再缩减 HCCL 缓冲并限制图捕获 | 2 | 2,232.20 | 37.78 | 43.18 | 21.62 | 742.5 |
| 再加 W4A8 融合 MoE，加入保护前 | 2 | 2,344.55 | 35.18 | 39.75 | 21.52 | 723.6 |
| W4A8 融合 MoE 加 SiLU 保护，保留版 | 1 | 2,330.28 | 35.41 | 39.83 | 21.39 | 726.2 |

两轮未加保护版分别实测 **2,353.72** 和 **2,335.39 tok/s/卡**，平均 TPOT 分别为 **35.16** 和 **35.20 ms**。相对固定 P 的原始 D，保留版这一轮提高 **36.12%**。所有 13 个计时轮均完整完成请求，D 本地前缀缓存查询和命中增量为 0。 [逐轮指标和精度计数](../results/case21/c1152.json) · [逐请求记录](../results/case21/c1152-requests.csv.gz)

- **P renderer 1 → 4**。保留原始 D 的同负载对照为 1,222.56 → 1,711.98 tok/s/卡，提升 **40.03%**。P 供流加快，D 同时实际解码由约 216 条增至 377 条。 [共享 Renderer 改动](https://github.com/jiaran-king/dsv4.1-optimize/pull/4)
- **三项紧凑布局前的 D 改动**。MoE 分发按每步实际 DP 批次缩容，草稿只对有效行做 SwiGLU，BF16 输入 embedding 迁移到 Host VMM。组合从 1,711.98 → 1,868.59 tok/s/卡（**+9.15%**）。档位缩容、算子耗时和释放显存各有单项证据，正式 C1152 吞吐只测了组合。 [MoE 分发](https://github.com/jiaran-king/dsv4.1-optimize/pull/1) · [SwiGLU](https://github.com/jiaran-king/dsv4.1-optimize/pull/2) · [Host embedding](https://github.com/jiaran-king/dsv4.1-optimize/pull/3)
- **KV 紧凑布局**。在同样的 15.26 GiB KV 预算下，长块的合计步长从 540,928 B 降至 369,280 B，长块数量约增三成。单加此改动的稳态吞吐提高 **14.75%**，全程吞吐提高 **14.70%**。这是 vLLM-Ascend RFC #21324 所述方向在旧版上的独立实现。我们的补丁只改 D，把 SWA 和压缩器状态放入同一个短池，并保留 P 的 PCP4、DSpark 5 和原 MooncakeHybridConnector。 [RFC #21324](https://github.com/vllm-project/vllm-ascend/issues/21324) · [上游 PR #22398](https://github.com/vllm-project/vllm-ascend/pull/22398) · [#10](https://github.com/jiaran-king/dsv4.1-optimize/pull/10)
- **HCCL 缓冲和图捕获**。将 D 的 HCCL 缓冲从 4,096 MiB 缩到 2,368 MiB，每 DIE 可用 KV 显存从 15.26 增到 18.82 GiB。最高图捕获档位从 432 收到 288 token 行，超出范围的批次走原 eager AllToAll。缓冲和图捕获改动在两轮同负载中提高 **4.10%**。宽批次冒烟覆盖了图外路径。诊断轮 3,520 MiB 的吞吐为 2,114.41 tok/s/卡，紧凑基线在线复跑一轮为 2,105.78 tok/s/卡。 [CANN 缓冲约束](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/850/API/aolapi/context/ops-transformer/aclnnMoeDistributeCombineV2.md) · [#11](https://github.com/jiaran-king/dsv4.1-optimize/pull/11)
- **W4A8 融合 MoE 与共享专家激活顺序**。时间线显示共享专家的向量激活与融合路由算子争用资源。共享 gate/up 投影可继续重叠，向量激活等融合算子的完成事件再提交。同一缓冲下，带 SiLU 保护的一轮相对仅调缓冲的两轮中位数提高 **4.39%**，平均 TPOT 从 37.78 降至 35.41 ms。加入保护前的两轮中位数提高 **5.03%**。 [#12](https://github.com/jiaran-king/dsv4.1-optimize/pull/12)

## 精度复审

| D 配置 | GSM8K 短题 | 约 130K 输入长题 | 宽批次数值正确 | 8 题严格单行格式 |
| --- | ---: | ---: | ---: | ---: |
| 原始 D | 1,276/1,319 | 189/192 | 1,127/1,152 | 4/8 |
| 紧凑 KV 版 | 1,281/1,319 | 189/192 | 1,127/1,152 | 3/8 |
| HCCL 缓冲与图捕获 | 1,276/1,319 | 189/192 | 1,130/1,152 | 3/8 |
| W4A8 组合，加入保护前 | 1,273/1,319 | 189/192 | 1,125/1,152 | 2/8 |
| 融合 MoE 加 SiLU 保护 | 1,269/1,319 | 189/192 | 1,128/1,152 | 4/8 |

保留版相对原始 D 的短题正确率变动 **−0.53 个百分点**。192 道长题的数值答案逐题一致，宽批次正确数多 1 条。复审发现融合算子固定执行 SwiGLU，因此增加 SiLU 条件。CPU 路径核对覆盖了 SiLU 走融合、SiTU 走已有实现。保留版完成了一轮吞吐复测。 [精度计数](../results/case21/c1152.json)

## 复现和回算

用 [部署和压测说明](benchmark.md) 的基线启动 D，P 选四个 renderer worker。按上述 PR 顺序给 D 应用补丁。HCCL 优化阶段可用启动脚本的 `--hccl-buffsize 2368`。使用同一批 4,608 条、C1152 和 RR=0 完成各轮。对公开 CSV 按 `trial` 分组，累加 `steady_selected=1` 行的输出 token，除以 JSON 对应轮次的稳态窗口时长和 8。 [阶段指标](../results/case21/c1152.json) · [逐请求 CSV](../results/case21/c1152-requests.csv.gz)
